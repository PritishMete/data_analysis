# Oracle cutover endpoint contract matrix

Audit baseline: PR #136 head `62641340598bca75de90e254c0cac2f2a2abde7c`.
The matrix is derived from `main.py`, `secure_excel/routes.py`,
`firebase_authz/middleware.py`, `dataset_storage/routes.py`,
`deploy/cloudflare/insightflow-api.js`, and the maintained Flutter callers.

## Conventions

- `JSON` means `Content-Type: application/json`; multipart rows use the
  boundary generated by the client. `-` means no request body.
- Protected routes require `Authorization: Bearer <Supabase access token>` and
  `X-InsightFlow-Workspace-ID`; resource-scoped routes also require
  `X-InsightFlow-Resource-ID` unless the resource is in the managed-dataset URL.
- Protected requests require a verified Supabase identity and active provider
  authorization. Missing/invalid auth is expected to be `401`/`403`; provider
  unavailability is `503`.
- Mutations below describe server-side persistence or in-memory state changes,
  not whether the uploaded source file is modified.

## Worker and deployment evidence

`deploy/cloudflare/insightflow-api.js` forwards path, query, method, headers,
and non-GET bodies to `http://127.0.0.1:8000` through `env.ORACLE_VPC`. It does
not rewrite endpoint paths or inject auth. The only Worker-generated responses
are CORS preflight (`204`), disallowed origins (`403`), and upstream fetch
failure (`502`). Its allowed header list includes `Authorization`,
`Content-Type`, and the workspace/resource/location/dataset/version/branch
headers used by Flutter.

Backend deployment commit evidence is not embedded in the Worker source. The
backend exposes `backend_commit` and `backend_git_sha` from `BUILD_GIT_SHA` or
`RENDER_GIT_COMMIT` at `/v1/build-info`; a live response must be compared with
the intended commit before cutover approval. No production deployment was
performed in this audit.

## Verification status

Read-only synthetic probes were limited to `GET /health`, `GET /v1/build-info`,
`GET /powerbi/ping`, and an allowed-origin `OPTIONS` preflight. Authenticated
write routes, file uploads, downloads of real datasets, diagnostics event
creation, and all persistence mutations remain unverified live because they
require credentials or would alter state. On 2026-11-28, the live responses
were `200`, `200`, `200`, and `204` respectively. Live `/v1/build-info` reported
backend commit `d1a63caa651c8abe0ca18584e96f30de053a4a45`, which does not match
the requested PR #136 head. See the test file for source-level coverage and
the final audit handoff for probe results.
